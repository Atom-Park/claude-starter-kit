# git 컨벤션 — 커밋·브랜치·게이트·PR

> 커밋·브랜치·PR **규약의 정본**. 실행 절차는 `commit-and-pr` 스킬이 갖는다 — 규약을 스킬에 복제하지 않는다.

## 커밋 메시지

- 형식: **`<type>(<scope>): [#<이슈번호> ]<한국어 제목>`**
- 제목은 **한국어**, 브랜치명·PR 제목은 **영문** (constitution ① 의 git 메타데이터 예외).
- 한 커밋 = 한 작업 단위. 규약·설정값 변경이면 참조층·집행층·실물이 같은 커밋에 들어간다.

```
feat({{SCOPE_EXAMPLE}}): 추론 엔드포인트 추가
fix({{SCOPE_EXAMPLE}}): #87 NA 처리 예외 수정
```

### type — Conventional Commits 표준 11종 (이 목록 외 사용 금지)

| type | 언제 |
|---|---|
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서만 변경 |
| `style` | 동작 변화 없는 포맷·공백·세미콜론 |
| `refactor` | 동작 변화 없는 구조 개선 |
| `perf` | 성능 개선 |
| `test` | 테스트 추가·수정 |
| `build` | 빌드 시스템·의존성 변경 |
| `ci` | CI 설정·스크립트 변경 |
| `chore` | 그 외 잡무 (위 어디에도 들지 않는 것) |
| `revert` | 이전 커밋 되돌리기 |

## PR

- 템플릿 `.github/pull_request_template.md` 의 절을 채운다: {{PR_SECTIONS}}
- 검증: {{VERIFY_CMDS}} 통과 — **명령과 실제 결과**를 적는다. 통과했다고 쓰지 않고 실행해서 나온 것을 적는다.
- 머지 조건: {{MERGE_COND}}
