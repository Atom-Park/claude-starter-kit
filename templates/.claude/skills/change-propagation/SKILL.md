# 변경 전파

같은 사실이 여러 층에 적혀 있다 — **① 참조층**(Claude가 읽는 것: 허브 · `docs/*` · `.claude/rules/*` · `.claude/skills/*`) → **② 집행층**(장치가 읽는 것: `.claude/settings.json` · `.githooks/*` · PR 템플릿) → **③ 실물**(코드·설정). 눈에 띄는 한두 곳만 고치면 불일치가 남는다. **전파는 Claude·장치가 실제로 참조하는 것만 고친다.**

## 순서

1. **지도표에서 그 사실을 찾는다** — `.claude-starter-kit/{{MAP_TABLE}}`. 행이 있으면 등재된 위치가 기본 대상이다.
2. **범위를 사용자에게 확인한다** — 전층(참조층+집행층+실물) / 문서만(참조층) / 실물만(불일치 감수·사유 보고). 임의로 전 층을 고치지 않는다.
3. **위에서 아래로 수정한다** — 참조층(허브 → `docs/` → `.claude/rules/` → `.claude/skills/`) → 집행층(`.claude/settings.json`·훅·PR 템플릿) → 실물.
4. **잔존을 검증한다** — `rg --hidden '<구값>'` 결과 **0건**. 킷 폴더·`.claude/`·`.githooks/`는 숨김 경로라 `--hidden` 없이는 통째로 빠진다.
5. **지도표를 갱신한다** — 지도표에 없던 사실을 고쳤으면 행을 추가하고, 위치가 틀렸으면 바로잡는다.
6. **보고한다** — 구값→신값 · 선택 범위 · 변경 파일 목록(층별) · 검증 결과 · 보류 항목과 사유.

## 이 리포에서 놓치기 쉬운 것

- **구조 자체를 바꿔야 하면 이 절차의 범위 밖이다** — 층 신설·폐지, 장치 변경은 관리자가 킷에서 처리한다. 멈추고 확인받는다.
- **규칙 3층은 짝으로 움직인다** — `docs/conventions/`(정본)를 고치면 `.claude/rules/`(집행 요약)도 같은 단위로 맞춘다.
- **스킬의 절차 본문은 킷 골격에서 온다** — 단계 서술을 고쳐야 하면 구조 개정 신호다. 리포 고유 주의사항·치환값만 이 절차로 고친다.
- **실물이 문서보다 앞설 수 있다** — 전파 전 실물을 먼저 검색해 어느 쪽이 최신인지 확인한다. 문서→실물 방향을 가정하지 않는다.
- 개인층(`docs/personal/` 내용물·`CLAUDE.local.md`·`settings.local.json`·**Claude 자동 메모리**)은 수정하지 않는다. grep에 걸리면 보고만 한다.
- **자동 메모리는 전파가 닿지 않는다** — 검색 대상도 아니다. 그래서 규약을 바꿨으면 보고 말미에 **"`/memory`에서 낡은 항목을 확인하라"**를 남긴다. 팀 규약이 메모리에 복제돼 있으면 정본을 고쳐도 개인 세션에서 구값이 살아남는다.

## 판단 기준

- **전파하며 고칠 곳이 몇 군데인지 세어 본다** — 같은 사실을 3곳 이상에서 고치고 있다면 그건 전파가 아니라 **중복 신호**다. 보고에 "이 사실은 N곳에 있다"를 적고, 단일 출처로 합칠 수 있는지 제안한다(합치기 자체는 구조 개정이라 별도 확인).
- **지도표가 출발점** — 사용자가 한 곳만 지목해도 지도표에서 그 사실의 행을 찾아 등재된 위치를 **전부** 확인한다. 지도표에 없으면 전수 grep으로 찾고, 끝나면 행을 추가한다(순서 5).
- **구조 개정은 이 절차의 범위 밖** — 여기서 다루는 건 **값·규약의 변경**이다. 3계층·방법론·운영 원칙 같은 구조 자체를 바꿔야 하면 멈추고 협의한다(경로: 킷 개정 → 관리자가 리포마다 직접 반영 → 판 표기 갱신). 구조 개정을 grep 전파로 처리하지 않는다.
- **외부 기준 존중** — 다른 시스템과의 계약에 걸리는 값(API 경로·스키마 등)은 기준 측이 정답이다. 기준 측에 맞추는 방향으로만 전파하고, 기준 측 변경이 필요해 보이면 먼저 확인받는다(관계는 지도표 "리포 특이사항"에 기록).
- **층 간 대조는 내용 기준** — 자동 포맷 훅에 의한 공백·표 정렬 차이는 불일치로 보지 않는다.
- **멱등** — 이미 신값인 파일은 건너뛰고 보고에 명시한다. 판단이 안 서는 매치(동음이의·우연 일치)는 고치지 말고 보고에 목록으로 올린다.
- **리포별 커밋** — 여러 리포에 걸친 변경이면 커밋은 리포별로 따로 하고, 각 리포의 커밋 규약·위반 지시 게이트를 따른다.
