# 커밋·PR

## 새 브랜치를 만들거나 커밋을 제안하기 전 — 공통 0단계

**이슈번호 대조**: 지금 작업을 {{ISSUE_SNAPSHOT}}의 "작업 이름"에서 찾아 대응하는 ID를 구한다. 이 번호를 **브랜치명·커밋 메시지·PR 제목에 동일하게** 쓴다(소스: {{ISSUE_SOURCE}} — `docs/conventions/git.md` 참조). **대응하는 항목이 없으면 번호 없이 진행해도 되는지 먼저 사용자에게 확인한다** — 임의로 번호를 짓거나 생략을 단정하지 않는다.

## 커밋 제안 전

1. **형식**: `<type>(<scope>): [#<이슈번호> ]<한국어 제목>` — 이슈번호는 위 0단계에서 구한 값.
2. **type·scope는 정본에서 확인한다** — `docs/conventions/git.md`의 {{TYPE_SCOPE}}. **로그 패턴으로 유추하지 않는다.** 표에 없는 값을 쓰려면 먼저 확인받는다.
3. **언어** — 커밋 제목 한국어 / 브랜치명·PR 제목 영문 / 본문·산출물 문서 한국어.
4. **게이트** — `git config core.hooksPath`가 `.githooks`인지 확인한다. 훅이 자동수정한 내용이 있으면 재스테이징 여부를 확인한다. **`--no-verify` 금지**(권한 규칙으로도 차단된다).
5. **브랜치** — 보호 브랜치 직접 커밋 금지. 작업 브랜치에서 작업하고 PR로 올린다. 새로 만드는 브랜치명에는 위 0단계 이슈번호를 포함한다(`docs/conventions/git.md` 브랜치 네이밍 절 형식).
6. **커밋은 사용자 승인 후 실행한다** — 메시지 초안을 먼저 제시한다.

## 보고에 반드시 넣을 것

- **검증 명령과 실제 결과** — 통과했다고 쓰지 말고 실행해서 나온 것을 적는다. 실패했으면 실패한 그대로 적는다.
- **보호 경로 수정이 있었으면 전건 목록** — 무인·자동 승인 모드였다면 감사 기록(`.claude/unattended-edits.log`)과 함께 명시한다.
- 스테이징에서 빠진 변경·보류 항목과 사유.

## 커밋 단위

한 커밋 = 한 작업 단위. 규약·설정값 변경이라면 **참조층·집행층·실물·검증이 같은 커밋에** 들어가야 한다(`change-propagation` 스킬 참조) — 나눠 커밋하면 중간 상태에서 불일치가 남는다.
